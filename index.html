STAGE 01 // RETRO ARCADE
LEVEL 01▲ LEVELS

CRAZY PONG

Easy68K Assembly · Retro arcade

Pong rebuilt from scratch in assembly with a twist: misses bounce off the wall, and every paddle hit sends the ball out at a random angle and velocity.

▼ CLOSE CASE FILE▶ OPEN CASE FILE

GOAL

Recreate Pong at the lowest level to understand what a game really needs: input, update, collision and draw.

HOW IT WORKS

  • Ball position and velocity update every frame.
  • Paddle hits pick a random rebound angle and speed, so no two rallies play the same.
  • Collision and physics are custom-built; the score is drawn as a 7-segment LED display.

TAKEAWAY

Managing registers and memory by hand gave me a deep respect for what engines abstract away.

LEVEL 04▲ LEVELS

C++ GAME ENGINE

Built from scratch · Unit tested

A data-driven engine with a hierarchical JSON runtime and a lightweight scripting layer, so designers can change behavior without recompiling. Our team shipped Vampire Hunters on top of it.

▶ VIEW ON GITHUB
▼ CLOSE CASE FILE▶ OPEN CASE FILE

GOAL

Build the systems every game needs (data, events, scripting) and keep them clean enough to grow.

HOW IT WORKS

  • Datum: a typed value container (int, float, vector, matrix, string) with resizable arrays, covered by unit tests.
  • Scope and Attributed: hierarchical runtime data for game objects.
  • ParseCoordinator and type handlers: read JSON into that data (Chain of Responsibility).
  • Factory: creates game objects and actions from data.
  • Event, EventManager, Subscriber: Observer-style messaging.
  • Action and ActionList: the lightweight scripting layer.

TAKEAWAY

Patterns and tests are what let a small team keep changing an engine without breaking it.
